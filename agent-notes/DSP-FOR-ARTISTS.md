# DSP for Artists — implementation reference

This topic preserves the **2026 implementation notes** originally recorded in the large root `AGENTS.md`. These are architectural references, not a guarantee that every behavior remains current. Inspect current source/tests before editing.

Core principles: one persistent workshop audio engine and canvas host across lesson navigation; browser microphone permission only on explicit action; oscillator state persists per lesson; audio monitoring stays muted unless enabled; presentation windows receive validated state/analysis frames via session-specific `BroadcastChannel` and do not request microphone access or create another audio engine. Resident voices are optional sources, not a dependency for manual lesson functionality.

## DSP for Artists workshop (2026-10-20)

- `/lab/dsp-for-artists` remains the prose course landing page and links to three viewport lessons: Audio Processing, Interference Patterns, and Make Some Art. DSP for Artists is an expandable nested item in the Lab navigation.
- The lessons share one session-persisted, serializable parameter model through their route layout. Each lesson applies declarative defaults only on its first visit in the browser session; explicit lesson/all resets remain available. Share links contain validated non-default controls in a `sketch` query parameter and never include microphone state or permissions.
- The responsive workspace keeps the canvas visible, uses independently scrolling instructions and controls on desktop, and moves controls into a MUI drawer on narrow screens. One course audio owner provides two oscillator tones or an explicitly enabled microphone; navigation cleanup stops tracks, oscillators, and the AudioContext.
- Byte-identical copies of `weather-music/sketches/fft-x-nothing.js` and `plane-waves.js` remain in `public/dsp-for-artists/` as reference fixtures. Runtime rendering ports their spectral composition, band assignment, peak tracking, phase/propagation history, signed pressure, palette, and blend algorithms behind the typed renderer contract in `src/lib/dsp-for-artists/renderer.ts`; it no longer executes either sketch or manipulates their controls. RMS and color pulse depths default to 2 at the course layer; plane-wave envelope controls are omitted.
- The shared Layers slider spans the original sketches' full 1–8 range. A single layer remains the course default and is selectable in every lesson that exposes layer controls.
- One persistent canvas host consumes typed analysis frames and switches all six modes without remounting. FFT/CWT analysis runs every 50 ms independently of the render loop; reusable arrays, history rasters, and plane-wave image buffers avoid per-frame allocation. Parameter changes call `setParameters` on the existing renderer. There are no workshop iframes, hidden legacy controls, DOM-label searches, synthetic input events, screenshot polling, or mutation observers.
- `scripts/profile-dsp-workshop.mjs` compares production builds with the presentation open. On the 2026-10-21 legacy bridge run, `b643a6a` measured 2.07 s initial canvas load, 14.4 fps, 1.18 s median and 1.29 s p95 slider propagation. On the 2026-10-22 consolidated runtime, the same headless Chromium scenario measured 121 ms load, 60.5 fps, 66 ms median and 68 ms p95 propagation.
- A persistent `DspEngine` owned by the shared course provider has one lazy Web Audio graph, independently routed oscillator generation/analysis/monitoring, reusable FFT/waveform/CWT buffers and kernels, 50 ms analysis cadence, microphone lifecycle, typed analysis frames, status/frame subscriptions, and deterministic teardown. The route-level shell keeps the provider, workspace, engine, canvas, controls, and lesson state mounted while lesson slugs change.
- Presentation opens `/lab/dsp-for-artists/presentation?session=<uuid>`. A session-specific `BroadcastChannel` sends validated parameter snapshots and live analysis frames; the presentation creates no AudioContext and requests no microphone permission.
- Palette sampling treats non-finite analysis values as the palette floor, and restored session controls pass through the same validator as share links. This prevents stale or malformed state from terminating the animation loop.
- Shared-controls consolidation replaces the legacy two-frequency/source switch with validated `oscillators[]` and independent microphone state. Oscillator play, visual visibility, waveform, frequency, dB level, cutoff, direction, phase, and band survive lesson/mode changes and share links. Microphone and oscillator analysis can run together; global mute controls only the monitor bus, and microphone monitoring remains off by default.
- Every lesson uses the same compact accordion panel (Microphone, each Oscillator, Spectrum, Layers, and conditional plane-wave Expression). The five visualization choices are independent from FFT/CWT, so Time-frequency resolves to Spectrogram or Scalogram. Conditional controls and renderer-specific blend choices are declarative. The canvas has no audio overlay; the top bar owns microphone, monitor mute, link, and presentation actions, and the AudioContext resumes from the first permitted user gesture.
- The provider persists three complete lesson sketches under `dsp-for-artists:v3:lessons`. First visits merge base and lesson defaults (1, 2, and 3 oscillators); navigation saves the departing sketch and restores the destination without remounting the canvas, renderer, or engine. Share parameters apply only to the addressed lesson. The shared oscillator-count selector supports 1–8, removes only trailing oscillators when reduced, and preserves remaining stable IDs/settings. “Reset all lesson sketches” explicitly resets all three; “Restore lesson defaults” changes only the active lesson.
- The 2026-10-22 fidelity pass restored Plane Waves radial source geometry, per-source band ranges, FFT/CWT and raw/relative analysis selection, sub-bin peak interpolation, proximity-aware tracking, and zero-layer behavior. Time-frequency history now honors linear/log frequency axes; circle angle distribution updates oscillator directions. Plane-only controls omit inapplicable Axis and Diffusion settings. The first-interaction audio unlock runs after a completed click so it cannot consume a microphone or monitor control click. The original public sketch fixtures remain byte-identical. Lint, type checking, production build, and all 87 Playwright tests passed; the two-canvas production profile sustained about 60 fps with warm loads of 109–118 ms and median automated input completion of 83–120 ms.
- The 2026-10-22 workshop UI pass keeps all renderer sources square and composites them with cover cropping, so responsive viewports no longer stretch the visual algorithms. Canvas backing dimensions follow device pixel ratio; Plane Waves uses a 540px reusable raster, and every mode receives the analyzer's shared time-domain waveform overlay. Microphone capture and visual visibility are independent. Controls are ordered Visualization, Microphone, Spectrum, Layers, Expression, oscillator count, and oscillators; Time hides visual-only controls, while Expression remains available in every lesson. Header microphone/monitor actions and oscillator transport actions use explicit labels and pressed states. Production profiling measured 195 ms cold canvas load, 60.2 fps, 90 ms median and 180 ms p95 automated input completion. Lint, type checking, the production build, all 18 workshop tests, and all 91 full-suite tests passed. The full-suite pass also corrected stale Moire Patterns title metadata and a navigation test selector left by the preceding IA change.
- Source activation was simplified on 2026-10-22: oscillator `playing` and microphone `enabled` now govern audio generation, shared analysis, waveform input, and visual participation together. Pausing removes the oscillator node and visual layer; disabling the microphone disconnects analysis/monitor routing, tears down its nodes, and stops capture tracks. Legacy saved `visible:false` values migrate to the corresponding inactive state, after which visibility is omitted. Oscillator count supports 0–8. Harmonics defaults to Linear with microphone and Oscillator 1 panels open; Interference defaults to Pressure with Oscillator 1 active, Oscillator 2 paused, both oscillator panels open, and microphone collapsed; Sandbox retains Rings and three oscillators. All 20 workshop tests and all 93 repository tests passed.
- All lesson oscillators now default to sine. Workshop rendering uses a contained square below the waveform band rather than cover cropping: Linear/Rings frequency boundaries and the time-history newest edge remain visible in wide and narrow viewports, with letterboxing where needed. Raster dimensions follow the displayed square and use bounded high-DPI supersampling, while the main canvas retains full device-pixel-ratio backing. Production profiling measured 133 ms load, 60.3 fps, 83 ms median and 100 ms p95 automated input completion. Lint, type checking, production build, all 21 workshop tests, and all 94 repository tests passed.
- Crest and Pressure now share a physical time-domain traveling-wave model with the waveform strip. Active oscillators retain waveform, frequency, level, and phase; microphone planes sample an eight-second live waveform buffer rather than an inferred dominant sinusoid. Spatial delay uses 343 m/s, a plane-only Spatial scale control defines meters across the square, and Propagation speed advances simulation time independently from wavelength with a 0.01× default. Pressure maps the signed source sum; Crest retains per-source palette/blend rendering from the same samples. The meter scale remains tied to the contained field through resize. Extreme microphone slow motion is limited by the finite rolling buffer and clamps at its oldest available sample rather than synthesizing unavailable history.
- The follow-up plane-wave repair normalizes waveform shape separately from physical level in Crest, making default-level sources visible while Pressure continues to sum physical signed amplitudes. The former spatial contour pass has been removed from both modes; individual sources remain visible in the waveform strip. Direction 0 increases distance from left to right, and `sourceSignal(t - distance/343)` advances features in that positive direction. Microphone planes now consume ordered 2,048-sample blocks from a same-origin AudioWorklet; an analyser suffix remains only as a compatibility fallback when AudioWorklet is unavailable. The renderer stores exact blocks in an eight-second circular buffer, uses absolute sample indices for interpolation, and clears the history when capture is disabled. Automated coverage checks rendered contrast, waveform changes in both plane modes, overlays, microphone contribution/removal, directional travel invariance, and opposite-phase signed cancellation. Headless visual inspection confirmed visible sawtooth Crest bands and Pressure contours; live microphone hardware still requires an interactive browser permission check.
- All workshop modes now use one full-width 50 ms waveform strip labeled as modeled virtual-listener pressure. The stable listener is at normalized field coordinates `(0.25, 0.15)` in the fixed 12 m plane model. Active oscillator traces use waveform, level, phase, and source direction; the live microphone analyser supplies its trace without waiting for the propagation buffer. Every source uses one shared vertical gain and appears faintly behind the prominent signed sum. Direction changes only this modeled pressure and the plane field; `oscillatorsFromParameters` deliberately omits direction, so synthesized and monitored audio are unchanged. Plane scale/playback remain fixed internally at 12 m and 0.01×; their controls and scale label were removed. The former unused `assignment` field was replaced by `layerSource`: Separate sources retains per-layer band assignments, while Combined output gives every spectral layer the analyzer's actual time-domain mixed FFT/CWT input; Crest combines signed pressure before its visual mapping. The waveform is independent of this setting.
- The Sandbox regression pass separates `waveGeometry` (linear/radial), layer arrangement (line/circle origins), layer rotation (none/even/fixed), global rotation, and each source's own direction. Controls no longer rewrite oscillator directions. All factory, lesson, and newly added oscillators start as sine at 0°, while saved explicit waveform/direction choices migrate intact; harmonic markers now default off. Legacy v3 lesson state migrates into `dsp-for-artists:v4:lessons`, including the new geometry fields. A synchronous initial measurement plus a one-frame layout recheck fixes the previously blank first Sandbox render without adding another animation loop. Pressure Screen/Multiply styling is applied only after signed summation, and the former main-field contour overlay pass is removed; per-source traces remain in the waveform strip. Sandbox still intentionally defaults to three sources, CWT, and radial geometry, so a meaningful comparison with Harmonics requires matching source count, FFT/CWT mode, and geometry. The focused production-browser suite covers initial paint, control independence, migration, pressure blending, contour removal, microphone contribution, waveform traces, and coincident-source phase cancellation.
- Layer rotation applies only to Circle arrangement. None gives every circular layer a 0° effective direction, Evenly spaced assigns `index × 360 / activeLayerCount`, and Fixed step assigns `index × angleStep`; Global rotation is added afterward. Line arrangement hides these controls and retains each source's direction plus Global rotation. Circle always exposes Layout radius, while Line exposes X/Y spacing. Renderer diagnostics expose effective directions for deterministic browser regression checks without mutating saved oscillator directions.
- Circle arrangement uses the same effective angles for both layer orientation and origin placement on the layout circle. Consequently None overlaps origins at 0°, Evenly spaced distributes origins around the full circle, and Fixed step advances both origin and orientation by Angle step. This keeps the controls visible with radial wave geometry, where orientation alone is rotationally symmetric. `data-layer-origins` and `data-layer-directions` support deterministic browser checks.

## Shared resident voice allocation and pitch mapping (2026-10-26)

- `src/lib/voices/pitch-mapping.ts` is the pure public mapping foundation. `mapEnvironmentalPitch(sourceFrequencyHz, options)` preserves the former resident-voices logarithmic mapping and 0.05–1 Hz defaults, clamps source and MIDI ranges, and returns fractional MIDI, rounded MIDI, and the continuous- or quantized-mode oscillator frequency. The existing octave UI is normalized to MIDI with `(octave + 1) * 12`; no visual mapping or MIDI pitch bend was added.
- `src/lib/voices/voice-allocator.ts` exports `VoiceAllocator`, `voiceIdentity`, and `DEFAULT_MAXIMUM_VOICES` (8). Updates are authoritative; invalid, inactive, absent, or disconnected voices release. Composite `streamId::voiceId` keys prevent cross-stream collisions. Continuing active voices retain their slots, free slots admit waiting voices by descending confidence and then composite key, and shrinking the limit releases assignments outside the retained slot range without moving lower slots. Returned allocated/released records are serializable and state is bounded by the configured maximum.
- Signal Voices exposes a global Maximum Voices control (0–128). One allocator result feeds browser oscillators and MIDI notes, while the existing per-stream Notes toggles, pitch controls, hysteresis, note-off/panic behavior, and full-active-set beat calculations remain intact. This does not alter the `resident_voices` contract, Pi analysis, or SuperCollider's independent `maxPolyphony` selection.
- Validation for this phase: lint completed with only the three pre-existing copied-fixture warnings, TypeScript passed, the production build passed, the focused pitch/allocator/resident-voices suite passed all 9 tests, and the complete Playwright suite passed all 116 tests.

## DSP for Artists Electric Sea input (2026-10-26)

- DSP for Artists now switches between Manual Oscillators and Electric Sea without replacing its `DspEngine` or renderers. Manual lesson oscillator arrays remain the persisted source of truth; Electric Sea supplies a temporary effective oscillator array, and switching back restores the untouched manual settings.
- `ElectricSeaSource` subscribes through the shared `RouterClient` only while Electric Sea input is selected, retains authoritative snapshots independently per `resident_voices` stream, clears unavailable streams on unready messages and all data on disconnect, and unsubscribes on mode change or provider cleanup. Notifications are batched to animation frames. Allocator slot numbers become stable DSP oscillator IDs so routine frequency/confidence updates configure existing engine voices instead of recreating them.
- Electric Sea controls select all or one observed stream and configure base MIDI note 48, 36-semitone span, continuous/quantized mapping, and maximum voices 8. Allocated voices use the shared pitch mapper and allocator, sine, direction/phase 0, raw band, a 4 kHz cutoff, and confidence-bounded level from -60 to -9 dB. Existing mute/unmute behavior remains authoritative and Electric Sea never unmutes monitoring itself.
- No router protocol, signal analysis, SuperCollider, Wave Interference, MIDI output, renderer, preset, or exercise behavior changed. Phase 2A validation passed lint (only the three pre-existing copied-fixture warnings), TypeScript, production build, and all 33 focused DSP/source browser tests.
- Phase 2A lifecycle correction: each observed stream expires independently after 30 seconds without `resident_voices`, releasing its allocation while other streams continue. Timers and snapshots clear on stop/disconnect. `RouterClient.acquireResidentSubscription()` now reference-counts consumers and replays the unchanged boolean subscription after reconnect, so leaving DSP cannot disable another resident-voice consumer. Electric Sea oscillators retain slot IDs and expose their composite upstream identity in optional `sourceVoiceKey` metadata. Focused stale, overlapping-owner, resident-voices regression, manual-mode, cleanup, and muted-monitor checks passed; TypeScript and the production build also passed.
- DSP rendering performance correction caps FFT/plane internal rasters at 480×480 while preserving CSS display size and high-quality scaling. FFT pixel-to-band geometry is cached until size/layout/axis/source geometry changes, and raw/low/mid/high channels now share one base spectral/relative transform per frame before channel masks and diffusion. Audio analysis, visual controls, and output semantics are unchanged.
