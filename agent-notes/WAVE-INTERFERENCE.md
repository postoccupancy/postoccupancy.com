# Wave Interference — implementation reference

This topic preserves the **2026 instrument-specific notes** originally in the root `AGENTS.md`. These details are references for code review and tests; check current renderer and source before making changes. Do not conflate manual audio, Electric Sea voices, or SuperCollider's independent allocation.

## Wave Interference instrument (2026-10-24)

- `/instruments/wave-interference` is a narrow exhibition controller built on the shared workshop `DspEngine` and its own `WaveInterferenceRenderer`. It keeps the three-column viewport, one persistent high-DPI canvas, link serialization, and session-specific presentation breakout. Byte-identical reference copies of `weather-music/sketches/fft-x-nothing-presentation.js` and `plane-waves.js` live under `public/wave-interference/`; the page-specific renderer ports their algorithms without an iframe or legacy controls. Do not route it back through `WorkshopRenderer`.
- The visible model is intentionally limited to FFT/Plane Waves, lines/rings, 1–8 layers, shared spacing, exposure, supported blend modes, and persistence. The four named presets cover the Cartesian product of visualization and geometry. FFT uses a fixed 256×256 raster. Plane uses the original **Pressure Sum** view on a fixed 360×360 raster, with logarithmic microphone bands, persistent peak tracking, historical amplitude/phase propagation, signed pressure summation, contribution-weighted spectral color, and Multiply/Screen composition. Even angles are always `45° + index × 360/N`; line placement and radial source placement are separate from direction.
- Microphone capture requires **Start audio**, accepts a selected input device and explicit channel 1–8, and routes that channel through a `ChannelSplitterNode` into analysis. The analyser is never connected to the destination. The level meter updates imperatively. Presentation receives analysis frames over `BroadcastChannel` and never requests capture.
- Direct Web MIDI is controller-window only and requires **Enable MIDI input**. Learn keys include message kind, one-based MIDI channel, and CC/note number. CC maps support absolute 0–127 and relative 1/127. Note mappings toggle on Note On; Note Off and zero-velocity Note On are ignored. Mappings and the selected controller ID persist in localStorage. Each mapping has a compact X removal action, and Clear all mappings removes every assignment while retaining the selected controller. The Presets mapping cycles or selects complete preset snapshots. Source spacing is one arrangement-aware mapping: it changes circle radius in Circle and changes X/Y together in Line. No messages are forwarded and no controller mapping is guessed. Presentation receives only validated visual state.
- Display input is 64 logarithmic center samples spanning the complete 60–6000 Hz range. Every center is sampled by linear interpolation in dB between its adjacent Web Audio FFT bins, exactly as in `fft-x-nothing-presentation.js`; do not aggregate bins or copy the first 64 entries from the engine's 256-band array. Raw/Relative is exposed in both visualization families and is MIDI-learnable. Relative uses the reference half-octave neighborhood median in power, positive log2 ratio, and per-frame peak normalization; Plane keeps raw peak-frequency tracking but derives band amplitude from that relative prominence. Persistence uses source timestamp deltas with the reference 50 ms initial delta and 1–500 ms clamp. The defaults retain Raw mode, gate 0, adaptive range off, contrast 1, response smoothing 0, persistence 0, and diffusion 0.
- Wave geometry (`lines`/`rings`) and source arrangement (`line`/`circle`) are independent in both renderers. Line arrangement uses X/Y spacing to separate source origins; circle arrangement uses circle radius. FFT Lines defaults to 8 layers, exposure 40, X/Y 0, Raw/Multiply. FFT Rings defaults to 3 layers, exposure 25, Line arrangement, X 125/Y 0, Raw/Multiply. Plane preset values remain independent complete snapshots. The shared placement coordinate system is based on the original 570 px field and is scaled into Plane's fixed 360 px raster. FFT angle defaults to 0° and Plane retains its independent 45° direction offset. Existing links without `arrangement` infer it from geometry and migrate legacy Plane `spacing`; legacy placement MIDI mappings migrate into the single Source spacing target. Do not add global translation to the spacing controls.
- Source spacing, source arrangement, and active-renderer angle offset have MIDI-learn targets. Angle offset rotates both direction and the source-origin line, so it remains visible with Line arrangement and radial geometry. Plane geometry cache keys include arrangement, all active placement values, direction offset, geometry, and layer count; cache creation remains deferred until rendering so batched control changes cause one rebuild. Placement changes preserve analysis and propagation history. The two accepted geometry/arrangement pairs retain their original distance equations. For the new Ring/Line combination, radial history begins at each actual source origin. For Line/Circle, circle displacement uses the fixed analysis-band center for its phase offset so small tracked-frequency changes cannot wobble the entire field. Out-of-range travel indices resolve to finite zero history instead of clamping distant areas to the last sample. Entering Plane Waves and its presets defaults to Screen blend. Plane RMS luminosity is enabled by default with the fixed reference color-pulse depth of 2; only its on/off switch is exposed.
- Plane propagation advances at 30 fps between analysis frames. Presentation reserves no waveform area. Once a presentation heartbeat is active the controller canvas shows an explicit paused-preview status and stops its duplicate render while capture, controls, MIDI, analysis, and broadcasting continue. A 1-second heartbeat with a 3.5-second lease resumes preview after close, reload failure, or disconnect without relying on `popup.closed` or unload delivery. Broadcast analysis frames contain only sequence/timing metadata and raw FFT bins consumed by this renderer.
- Plane pressure pixels reuse cached geometry indices/fractions and typed amplitude/phase lookup buffers. Geometry caches invalidate only for geometry, spacing, or layer-count changes. FFT mode skips plane-band tracking. Canvas diagnostics expose analysis duration and arrival gaps, render duration, frame interval, internal raster, directions, and render count.
- `docs/WAVE-INTERFERENCE-WINDOWS.md` records the offline Windows install/start procedure and the required temporary-internet dependencies. DJ2GO2 simultaneous ownership by the browser and Ableton is hardware/driver dependent and must be tested on the exhibition PC; the site deliberately adds no MIDI bridge or controller gate.
- `tests/wave-interference.spec.ts` covers exact FFT center interpolation, 100/1000/4000 Hz placement, timestamp-delta persistence, bounded presets/state and legacy placement migration, canvas persistence, device/channel capture, independent placement/arrangement MIDI mappings, MIDI identity/persistence/encoder modes and unique event keys, all eight visualization/geometry/arrangement combinations, both plane blends, extreme placement values, fixed rasters, directions, lean frame serialization, heartbeat recovery, and presentation ownership. `scripts/profile-wave-interference.mjs` profiles the production build with Chromium's fake media device through real Web Audio and focuses the projector window. Before geometry caching, a five-second run measured plane rendering at 9.8 ms median/30.6 ms p95. After caching, the 120-second run measured analysis at 0.1/0.2 ms median/p95, rendering at 10.0/10.7 ms, frame intervals at 33.3/33.4 ms, analysis arrival gaps at 56.7/57.9 ms, zero long tasks, and zero background controller renders. The automated run uses two pages, not two physical displays; verify the real dual-display path on the exhibition PC. Keep the source fixtures byte-identical when the upstream weather-music sketches change.
- Phase 2B adds Manual Oscillators / Electric Sea input selection without replacing the canvas, renderer, `DspEngine`, saved `WaveState`, presets, geometry controls, microphone analysis, or MIDI controls. It reuses `ElectricSeaSource`, whose allocated oscillators provide live mapped frequency/confidence and subscription cleanup; the same source payload is forwarded to presentation mode. Manual mode remains the unchanged default and restores its existing state.
- Electric Sea plane propagation is keyed by each oscillator's `sourceVoiceKey`, not its reusable slot ID. Released identities remain as bounded, zero-input histories for 40 seconds (maximum 64 retained identities), allowing emitted fronts to leave the 360 px field while a new identity can reuse the same geometry slot without rewriting prior frequency/phase history. Geometry remains derived from existing line/circle placement, X/Y spacing, radius, linear/radial form, rotation, and the source's stable slot. FFT mode converts the live oscillators into the existing bounded 64-band input representation. Focused Wave Interference and shared-source tests, TypeScript, lint, and the production build passed.
- Pitch-change correction: every plane history sample now stores its emission-time spatial wave number alongside amplitude and phase. Delayed lookup interpolates that stored value and applies it to the geometry phase distance, so already emitted fronts keep their original spacing after a resident voice changes pitch while subsequent fronts use the new wavelength. The focused live-pitch regression and the original manual plane raster test passed, as did TypeScript and the production build.

## Wave Interference Electric Sea rendering correction (2026-10-27)

- Electric Sea substitutes Maximum Voices for the manual Number of Layers setting; it does not introduce alternate geometry or blend semantics. FFT and plane layouts retain the original angle, spacing, radius, arrangement, scaling, exposure, and layer-normalization rules.
- Environmental plane amplitude is derived from confidence independently of audio dB. Retained histories still preserve emission-time identity and wavelength until they leave the field. Manual rendering remains unchanged.
- Follow-up integration correction separates upstream eligible voices from locally allocated voices in `ElectricSeaSource`; DSP reports “available / allocated” and Wave Interference reports “available / visualized.” Neither count claims parity with SuperCollider's independently filtered, hysteretic `maxPolyphony` selection.
- Allocated environmental voices contribute independently smoothed frequency/amplitude peaks to one shared FFT spectrum. The unchanged original FFT renderer repeats that spectrum through Maximum Voices layers, exactly as manual mode repeats its shared microphone spectrum through Number of Layers.
- Environmental amplitude follows the checked-in SuperCollider base formula: `clamp(0.18 * confidence, 0.015, 0.22) / eligibleDeviceVoices^0.35`. SC-only sensor gain, mute, master volume, confidence threshold, and selection hysteresis are unavailable in `resident_voices` and are intentionally not inferred. Electric Sea Exposure uses the same additive sensitivity scale as the manual analysis path, centered at the existing default, rather than post-render brightness gain.
- FFT Add, Multiply, Maximum, and Blend use the exact `main` formulas for both inputs, including geometric-mean Multiply and layer averaging. Frequency/amplitude transitions use the checked-in SC smoothing constants (0.18 s / 0.35 s). No Electric Sea-specific direction, origin, blend, or brightness rule remains.
